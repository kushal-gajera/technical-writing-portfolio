# Documentation Fundamentals

Technical documentation explains a product, process, program or system so that readers can understand it and use it correctly.

## Common types of documentation

| Type | Purpose |
|---|---|
| User guide | Helps users complete a task |
| Tutorial | Teaches a process step by step |
| API documentation | Explains classes, functions and interfaces |
| Reference | Provides concise facts for lookup |
| Technical report | Presents work, methods and findings |

## Writing clearly

- Decide who will read the document and what they need to do.
- Use precise, familiar words and explain technical terms.
- Divide long material into meaningful headings.
- Use numbered steps when order matters.
- Add examples where they make an idea easier to understand.
- Check facts, spelling, links and formatting before sharing.

## A simple documentation workflow

**Plan → Research → Outline → Draft → Review → Publish → Maintain**

## Before publishing

- [ ] The purpose and audience are clear.
- [ ] Headings follow a logical order.
- [ ] Instructions can be followed.
- [ ] Examples match the explanation.
- [ ] References are included where needed.
- [ ] The final document has been reviewed.

## Practical activity

Choose a small task from a tool you use. Write a one-page guide with a purpose, prerequisites, numbered steps and an expected result.
